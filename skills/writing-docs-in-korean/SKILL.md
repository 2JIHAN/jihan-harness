# 한국어 문서 작성 규약 (writing-docs-in-korean)

문서는 의사결정의 근거와 시스템의 제약을 군더더기 없이 고밀도로 전달하기 위해 존재한다. 한국어로 문서를 생성, 수정, 축소할 때 본 규약을 적용한다.

---

## 1. 범위 규율과 사족 배제

- **섹션 본래 목적에만 집중** — 파일과 해당 섹션의 고유 주제에 직접 기여하는 사실만 적는다. 사실이고 유익하더라도 주변 흐름을 벗어나면 사족이므로 제외한다.
- **틀린 내용은 설명 없이 삭제** — 잘못되거나 만료된 내용은 삭제 자체로 해결한다. 왜 틀렸는지 사유를 설명하며 빈 공간을 메우지 않는다.
- **1개 사실은 1개 위치에만 서술** — 동일한 사실을 편의를 위해 중복 기재하거나 불필요한 교차 참조를 만들지 않는다.
- **도입부 사족 배제** — "본 문서는...", "이 문서의 목적은...", "다음과 같습니다"와 같은 메타 안내문 없이 곧바로 본론에 진입한다.

---

## 2. 삭제 흔적(툼스톤) 없는 정리

- **완전한 삭제** — 문서나 항목을 줄이거나 폐기할 때는 블록 전체를 깨끗이 삭제한다.
- **묘비명 메모 금지** — 삭제된 내용을 `<details>` 태그로 보존하거나, "YYYY-MM-DD 삭제됨", "폐기 사유" 등의 툼스톤 메모를 남기지 않는다. 버전 관리(Git) 히스토리가 기록을 이미 보존한다.
- **참조 링크 동시 정리** — 항목을 삭제할 때 다른 문서에서 해당 항목을 가리키던 링크도 함께 정리한다.

---

## 3. 고밀도 서술과 자연스러운 한국어 문체

- **구조적 문서의 체언 종결** — 개조식 목록, 정의 항목, 규격서에서는 기계적인 `~이다.`를 남발하지 않고 깔끔한 체언(명사형)으로 종결한다.
  - *권장*: `- **정의** — LLM 대화 컨텍스트에 매 턴마다 상시 주입되는 전역 규약`
  - *지양*: `- **정의** — LLM 대화 컨텍스트에 매 턴마다 상시 주입되는 전역 규약이다.`
- **동작 및 불변식 서술** — 시스템 규칙이나 엔지니어링 제약은 명확한 선언형 서술어(`~한다`, `~않는다`)로 끝맺는다.
- **인위적 대칭 조어 금지** — 개념을 억지로 반으로 쪼개 대칭 카드(예: `남는 것` vs `지워지는 것`)를 만들지 않고, 한 덩어리의 자연스러운 문맥으로 서술한다.
- **큰 흐름 위주 서술** — 최종 도달한 결과와 핵심 흐름만 기록한다. 사소한 시도, 중간 시행착오, 버린 가설은 기록하지 않는다.
- **다차원 정보의 표 활용** — 2개 이상의 대상을 동일한 기준으로 비교할 때만 표를 사용한다. 단일 대상 서술에는 개조식 목록을 쓴다.

---

## 4. 독자에 따른 문서 분리

작성 착수 전 문서의 주 독자가 사람인지 모델인지 구분하여 서술 방식을 달리한다.

| 구분 | 사람이 읽는 문서 (기획서, README, ADR, 가이드) | 모델이 읽는 문서 (스킬, 규칙, 프롬프트) |
| :--- | :--- | :--- |
| **목적** | 가독성, 빠른 훑어보기, 직관적 이해 | 결정론적 지침 준수, 명확한 키워드 색인 |
| **문체** | 자연스러운 문어체, 개조식과 표의 적절한 조화 | 엄격한 명령형 지침 (`~한다`, `~하지 않는다`) |
| **구조** | 개념 풀이, 점진적 요약, 시각적 구조화 | 1줄 1규칙, 조건 우선 서술 (`~할 때, ~한다`) |
| **수정** | 흐름을 부드럽게 윤문하고 접속사 다듬기 | **윤문 금지** (불릿을 문단으로 합치지 않음) |

### 모델용 문서 작성 시 필수 준수 사항
1. **불릿 구조 유지** — 불릿 목록을 산문 문단으로 합치면 규칙의 고유 주소가 사라지므로 불릿 형태를 유지한다.
2. **1줄 1규칙 원칙** — 한 불릿 안에 여러 제약을 복합문으로 섞지 않는다.
3. **조건 우선 서술** — 상황에 따른 행동 규칙은 `~할 때, ~한다` 형식으로 조건을 앞에 둔다.
4. **자명한 규칙에 이유 설명 생략** — 새로운 상황에서 응용 판단이 필요한 경우에만 한 줄 이유를 붙이고, 자명한 규칙에 설명을 달아 노이즈를 만들지 않는다.
